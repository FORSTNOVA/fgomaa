# FGO-MAA

Windows 上的 FGO 日常、周常与普通关卡自动化助手，使用 ADB、OCR 和 Chaldea Laplace 战斗模拟。

当前版本：**v1.0.0-preview.20261105**。这是预览版本，活动剧情自动推进尚未实现。

## 下载与运行

从 [Releases](https://github.com/FORSTNOVA/fgomaa/releases) 下载 Windows 压缩包，完整解压后运行 `FGO-MAA.exe`。请保留整个目录，程序依赖 `_internal/`、`data/`、`src/` 和 `runtime/`。

1. 启动模拟器并选择设备；多设备时明确选择目标设备。
2. 导入自己的完整 Chaldea／FGO 账号 JSON 或 HAR，包含从者、礼装和任务记录。
3. 从日常、周常、自动推关中选择任务；建议先使用“仅模拟预览”。
4. 从大厅或目标地图启动。识别、模拟、编队、装备或战斗失败时停止，后续队列保持未执行。

公开包不带账号、抓包数据、HTTPS 证书私钥、历史进度或运行日志。内置 HTTPS 抓包没有预置证书，请使用 JSON/HAR 导入账号；本仓库没有提供证书自动生成配置流程。

## 当前功能

- 日常免费召唤、友情召唤、日常本和任务奖励处理。
- 周常任务识别、最低 AP 路线规划与自动执行。
- 已适配自由关卡、日常本和活动本的自选队列，逐关模拟、配队、装备、战斗和结算。
- 独立“关卡模拟与作战”模块：选择关卡后按已导入的从者练度与礼装配队，展示阵容、礼装等级／满破、伤害和 NP 结果。默认仅模拟；勾选自动跳转后共用编队、装备与战斗执行器。
- 已开放普通自由关卡的自动首通：实机核对当前阶段，完成整关后再选择下一关。
  - “全部已适配章节”按实机橙色数字角标逐层进入章节和地点，匹配准确关卡后读取阶段、模拟配队；同一地点的多张关卡卡片会滚动查找，重复画面或无法匹配时停止并保存截图。指定章节仍按 AP 排序选关。
  - 首通数量支持任意正整数，取消“最多完成”勾选即不限关数；AP 预算与果实上限独立控制。
- 关数、AP 预算、体力恢复和果实个数上限四个独立开关；取消上限勾选即不限。
- 赤铜果实按当前关卡的 AP 缺口一次选足；其余果实逐个使用，未知使用结果停止且不重复确认。
- 推荐从者与礼装自动选取、等级／满破／装备槽位复核，失败重试后停止。
- 战斗候选包含常规连发、三打手轮换和低血量普通攻击；初始 NP、色卡和宝威等礼装均须模拟通过。

“关卡模拟与作战”默认只挑战 1 场、AP 预算 100、不使用果实。将场次上限设为大于 1 或关闭上限，即可周回所选关卡。首场按关卡卡片核对 AP 并验证编队。之后优先通过游戏的「连续出击」沿用编队，每场重新选择助战。弹窗无法核对 AP 或需要补体时，回到关卡列表按原设置处理。AP 预算按实机显示计入，出击或补体结果不明时停止。

模拟使用目录标注的阶段。已适配的普通关卡无需导入通关记录即可发起自动作战，出击前会核对实机关卡及阶段。自由关卡的前置阶段由自动首通推进。助战按方案模拟，实际出击时须找到并核验匹配助战。

### 手动模拟

在“关卡模拟与作战”中将配队模式切换为“手动选择与模拟”。六个槽位按 **5 名自有角色＋1 名自定义助战** 计算，1～3 号位前排，4～6 号位后排。自有角色与礼装按导入的实际练度使用；助战可自设等级、宝具、主动／附加技能、芙芙、再临、技能／宝具版本，以及礼装等级和满破。御主礼装使用账号已记录的等级。

可编辑最多 30 回合的技能、御主技能、换人和宝具顺序；同回合宝具链支持 1～3 人。操作始终追踪最初编队槽位，换人后仍指向同一角色。手动计算严格照顺序执行，冷却、未解锁、角色不在前排或 NP 不足时显示停止位置，不自动补技能或重排。任意三卡普攻只在保守穷举证明可清场的低血量范围内可用。

修改配置会中断正在进行的手动模拟并使旧结果失效，可更换礼装后重新计算。保存／另存方案会记录关卡、六人编队、礼装、助战参数、御主礼装和完整行动顺序；方案存放在本地 `.app_profile/manual_plans/`，重新打开软件可载入。运行记录在 `.app_profile/manual_runs/`，结果绑定本次输入，不复用旧方案结果。

手动模式仅计算和保存，不自动出击；目前按最低伤害浮动、仅己方行动计算，不计敌方攻击或未建模机制。模拟编队允许多个槽位配置同名礼装，助战礼装独立设置；实际持有份数与实机装备结果仍需核对。

角色选择支持星级、职阶多选筛选，并可与文字搜索组合。可直接指定角色宝具形态，显示宝具名称、单体／全体和色卡；玛修可切换四星／五星灵基并绑定对应数据，无需重新导入账号。

### 逐步战斗与录制

逐步战场采用 FGO 风格横屏布局：上方敌方 HP／蓄力和目标，下方前排技能、HP／NP 与 Attack，右侧御主技能；选卡时显示宝具卡、五张普通卡、暴击概率及 1st／2nd／3rd 顺序标记。编队配置可折叠，后排、状态效果、伤害倍率和 AI／脚本记录仍可查看。

技能成功后提示技能名称和目标，计算期间及结果返回后高亮本步行动角色；攻击显示目标的合计伤害飘字、伤害次数和逐目标数字。HP／NP 条从上一步数值平滑变化，并标明增减。短提示约2.4秒淡出，战场下方保留最近一步结果，不需等待动画才能继续操作。回退、重做与载入显示“状态恢复”，不重播旧攻击；失败或中断不会显示成功反馈。反馈仅由已确认场景生成，不写入录制或影响随机结果；系统减少动态效果时保留文字结果。

优先使用 Atlas 公开的从者立绘、头像、指令卡人物图和技能图标，按进场快照中的再临、灵衣及技能版本选择，图片缓存于本地 `.app_profile/battle_assets/`。首次加载图片需要联网；缺图显示占位，不影响技能、选卡和计算。当前是静态立绘的实机风格界面，战场背景及控件由前端绘制，尚未接入原版战斗模型动画和宝具演出。素材加载与模拟随机数、保存、回退及重做独立。

将配队模式切换为“逐步战斗与录制”，使用同一套六人编队、概念礼装、御主礼装和自定义助战配置，点击“进入模拟战斗”。战场显示当前波次、敌方 HP／蓄力、六人 HP／NP、前后排位置、技能冷却及生效中的效果；选择技能和目标立即计算。点击 Attack 进入选卡，从本回合五张普通卡和可用宝具中按顺序选满三张，再“确认三卡攻击”。普通卡和宝具可任意混排，首卡加成、同色链、Brave Chain 的 Extra 攻击和逐卡伤害／NP回收交给原生引擎结算。

每名前排角色的五张普通卡组成牌组，每回合随机发五张；未选中的手牌也会弃掉，三回合用尽十五张后重洗。御主换人保留所在位置的卡位，退场补位重新构建牌组。界面显示卡片归属、颜色、暴击概率及已选顺序；可撤销最近选卡或返回技能界面，反复打开选卡不会重新抽牌。暴击星按集星权重与可计算的集星增益分配，并计入 Quick 首卡的暴击加成。

敌人存活时进入敌方阶段，可点击“敌方行动一步”逐次执行，或“执行剩余敌方回合”。新进场按公开关卡 AI 的条件、优先级与权重选择行动，支持思考节点跳转、敌方技能、普通攻击与宝具；场地、换血条、退场、技能／宝具及回合触发可调用反应技能和 BattleScript 序列。嘲讽、受击NP、伤害、退场、后排补位与回合末蓄力由引擎处理。展开“AI 与脚本记录”可查看执行节点和技能，敌方效果显示在对应单位下。

选关与选人操作不写入战斗录制，成功进场后才保存配置快照并开始记录。点击“返回选人”会恢复进场前的角色、礼装、宝具形态和御主礼装配置，保留已有录制；计算中也可返回，等待原任务结束后可再次进场。“中断计算”仅停止当前一步。战斗中可回退、重做或点击历史步骤恢复。回退后执行新的操作会从该处重新分支。修改关卡或编队后，重新进场会开始一份新的录制，上一场可从已保存的录制中载入。冷却、NP 不足、后排无法行动及未支持机制等失败不计为有效步骤。

进场时保存关卡、阶段和编队快照。新版录制的 `recognition` 字段提供刷关识别所需的关卡 ID、队伍槽位、从者、助战、概念礼装和御主礼装信息。每个有效战斗操作自动保存，也可命名另存。录制文件和带随机种子的进场快照存放在本地 `.app_profile/interactive_simulation/`，重启后可从“已保存操作录制”载入。进场同时冻结敌方 AI、脚本和引用技能。每次计算重放同一快照的操作前缀，因此手牌、暴击、概率效果、敌方决策和伤害乱数在同一操作前缀下保持一致。旧录制可继续载入。

新逐步模拟的每次伤害计算按卡／目标独立抽取整数 900～1099，再除以1000作为倍率；多段攻击沿用该次伤害计算的同一倍率，记录中显示实际值。概率效果也使用冻结种子的随机判定。这仍是公开数据与 Laplace 可支持机制的本地模拟：特殊条件、目标规则、脚本命令或效果未支持时，会报告具体 AI／脚本节点并停止，不视作普攻或成功跳过。当前不支持全部高难／剧情服务器机制，详见集成说明。模拟录制不捕获实机触摸；点击“按录制刷一场”可连接所选模拟器，核对进场快照的关卡与队伍，按波次／回合执行技能、宝具和换人，普通卡结合实机手牌与优先级选择。识别不一致时停止；此入口会实际操作游戏，模拟通过不等于实机保证通关。

### 关卡目录和导航

目录来自 [Atlas Academy](https://api.atlasacademy.io/)，启动时检查更新，每 24 小时条件刷新，也可点击“全量刷新关卡库”。敌人阶段数据按需下载。国服没有完整敌方配置时，可显式回退到同 ID、同阶段的日服数据；结果记录数据来源。

目录中存在关卡代表资料已收录。能否执行还取决于导航适配、开放时间、账号通关或前置记录和模拟结果；列表会显示不可执行原因。

已接入以下普通自由关卡的导航逻辑：第一部、第 1.5 部四章、异闻带 1～7（亚特兰蒂斯和奥林波斯独立识别）、平安京、Traum，以及奏章Ⅰ～Ⅳ。地点点击仍要求实际 OCR 确认，未知地图不会放行。不同剧情进度下的复杂地图切层尚未全覆盖。

### 万圣节 2026

单独适配“终结·万圣节2026～于南瓜星闪耀的歌姬～”的 9 个普通活动周回本。可按“活动关卡”筛选并加入队列，出击前需在实机找到已开放的目标关卡。

先手动完成必要的活动剧情，再导入完整新账号记录。软件核对准确活动横幅、地图背景特征、地点改名、关卡名称和 AP。活动过期、未满足前置、一次性挑战和高难等会拦截。其他限时活动需要分别适配。

本次活动地图、首通和战斗尚未完成实机验收；普通本第一仓储库已通过本地原生 Laplace 的 3T 预览。不会自动推进活动剧情、选择剧情分支或刷点数解锁下一节。

## 源码运行

建议使用 Windows、Python 3.13；发布环境已用这一组合验证。源码仓库不存放大型 Flutter 运行二进制，请从同版本 Windows 发布包取出 `runtime/laplace/`，放入源码根目录的 `runtime/laplace/`。对应上游源码和许可证已随仓库及发布包保留。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

CLI 示例：

```powershell
# queue.json: [{"quest_id":"fuyuki_x_a","runs":1}]
python -m src.workflows.quest_runner --account account.json --queue queue.json --preview
python -m src.workflows.quest_runner --account account.json --queue queue.json --device 127.0.0.1:16416
```

运行记录只写入本地 `.app_profile/`。停止后重新核对游戏状态再启动，中断的战斗不会直接计为通关。账号文件和证书目录已从 Git 提交范围中排除。

## 测试与构建

```powershell
python -B -m unittest discover -s tests
```

本版发布前执行 Python 全量回归与前端 Node 测试，具体结果见 GitHub Release 发布说明。新增敌方技能、公开AI思考跳转、场地／换血条反应、脚本序列／变量／强制胜负、逐目标随机伤害及未知节点阻断测试。随机手牌、混排、受击NP、退场／全灭和保存回退也已使用隔离耐久测试、真实后端及原生引擎验证；界面验证保存回退位置后重载、重做恢复相同HP／倍率／AI记录，正式软件目录接口与原生计算通过。未修改敌人数据的奥尔良栋雷米公开样本也验证了AI节点跳转。部分测试需要 Windows 原生运行时和联网获取公开游戏数据，本地模拟通过不等同于实机战斗验收。

- Windows 打包：`python build_exe.py`（需安装 PyInstaller，生成目录在 `dist/FGO-MAA/`）。
- 同步当前源码与资源：`python sync_dist.py`。
- 生成排除个人数据的公开发布包：

```powershell
python scripts/package_release.py --version v1.0.0-preview.20261105 --output dist/FGO-MAA-v1.0.0-preview.20261105-windows-x64.zip
```

发布脚本会排除账号、证书、运行历史和重复外部资源，并保留依赖通知和 Laplace 对应源码；压缩完成后校验 ZIP，生成 SHA256 文件。

Laplace 构建和算法边界见 [integrations/laplace/README.md](integrations/laplace/README.md)，本次变化见 [CHANGELOG.md](CHANGELOG.md)，第三方来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。项目自有代码目前未另行指定统一开源许可证，第三方组件保留其原有许可证与署名。
